# AGENTS.md — Development Guidelines

Rules for any AI agent working in this repo.

---

## Docs First

Before implementing anything, read the relevant `docs/` files:

- `docs/architecture.md` — stack, module responsibilities, data flows, scheduled tasks
- `docs/database.md` — full schema with behavioral notes
- `docs/commands.md` — all slash commands
- `docs/reputation.md` — reputation system
- `docs/llm.md` — LLM integration (BotCommentary, LLMClient, player_context.md)
- `docs/incomplete.md` — known issues, missing features, debug code in production

---

## Where Things Live

- **All config** → `config.py`. No hardcoded numeric values, thresholds, or channel IDs in modules.
- **All SQL** → `database/manager.py`. No raw queries anywhere else.
- **All Discord embeds** → `utils/embeds.py`.
- **All LLM messages** → `modules/bot_commentary.py`. Never write hardcoded Discord messages that should be dynamic.
- **Player personal context** → `player_context.md`. Read by the LLM on every message.

---

## LLM Integration

Any message that should be generated by the AI goes through `BotCommentary`, not hardcoded strings.

To add a new message type:
1. Add a method to `modules/bot_commentary.py` with a descriptive user prompt and a static fallback string.
2. Call `self.llm.generate(self._system, user_prompt)` — returns `None` if the LLM fails.
3. Return the fallback if result is `None`.
4. Document the new method in `docs/llm.md`.

The system prompt (Tofik persona + player context) is already built — you only write the user prompt.

---

## Documentation

- **Document every edit or addition.** After implementing something, update the relevant `docs/` file. If it's a new file or system, create a new doc.
- **Do not document removed features.** If something is removed, delete all mentions of it from `docs/` as well.
- **`docs/incomplete.md`** must stay accurate — mark items as done when they're implemented, add new known issues when discovered.

---

## Working with the User

- **Always ask questions before implementing** if the need isn't fully clear.
- **Narrow down the requirement** — ask about scope, edge cases, preferred behavior. Don't assume.
- **Get details** — a vague request like "add a leaderboard" needs: what data, what channel, what trigger, what format.
- One focused question is better than five at once. Ask the most blocking question first.
